# Conpass conventions

Conpass helps KubeCon NA 2026 attendees plan their days: what to see, how far apart the rooms are, and who to meet. It's a hackathon project that must work in a live demo on phones, so favour reliability over cleverness.

## Repo layout

- `apps/<service>/` holds one deployable service each. Today that's only `apps/web` (Next.js 15 App Router, React 19, TypeScript, Tailwind 4, zustand).
- Shared code that more than one service needs goes in `packages/`. Don't copy it between apps.
- A PR should touch one service unless it's deliberately changing a contract between services (see the API contract rule).

## TypeScript

- Strict TypeScript. No `any` and no `@ts-ignore` without a comment explaining why.
- Shared domain types live in `apps/web/src/lib/types.ts`. Extend them there rather than redefining shapes inline.
- Code style: double quotes, semicolons, named exports, short doc comments on exported functions.

## Scheduler logic

- Everything in `apps/web/src/lib/scheduler/` stays **pure functions**: no `fetch`, no Elasticsearch client, no `Date.now()` (take the time as a parameter), no React.
- Any behaviour change in the scheduler needs a test in `apps/web/tests/` (vitest).
- Times are epoch milliseconds internally. Convert to conference-local time only for display, via `src/lib/time.ts`.

## Elasticsearch

- All access goes through `es()` and `INDEX` in `apps/web/src/lib/es.ts`. Don't create clients elsewhere or hardcode index names.
- Mapping changes go in `src/lib/indices.ts` together with any `scripts/seed.ts` change they need.
- Search, recommendations and gap fill must keep working when Elasticsearch is down: they fall back to local logic. Flag any change that removes or bypasses a fallback.
- Elastic Cloud Serverless rejects shard/replica settings. Don't add `settings.number_of_shards` and the like to index creation.

## Data

- `apps/web/data/sessions.json` is generated by `scripts/import-schedule.ts`. Don't hand-edit it.
- Use real event data. Don't invent sessions or speakers. The one exception is themed lunch tables.
- Walking times and room capacities in `data/venue.json` are estimates; label them as such in the UI.

## UI

- Mobile first. Every screen has to work at phone width (360px) with no horizontal scroll.
- Accessibility counts: tappable targets of at least 44px, real `<button>`s for actions, text alternatives for icons.
- Refer to people (attendees, speakers) as they/them in UI copy.
